# Paper-code release acceptance

The deliverable is the code repository for the supplied LAST main paper and
updated supplement, not a collection of server-only experiment logs. Results
must be generated by the released implementation and traceable to its revision.
The checklist below is intentionally incomplete until verified.

Installation evidence: `results/fresh_environment_installation.json` records a
new Python 3.10 virtual environment installing `.[video,test]`, successful
`pip check`, 59 passing tests and CUDA/L40 detection. This used the working
repository rather than a pinned fresh checkout. Real-video validation and the
separate quality/baseline environments are not covered by that installation
receipt, so the clean-environment acceptance item remains open. Subsequent
`results/fresh_environment_reader.json` verifies one real Hunyuan I2V video in
that environment without historical overlays: clean512/512 and drop30=371/512,
matching old correct-bit counts. This does not cover fresh-checkout generation,
other model/mode combinations or the quality/baseline environments.

The pinned fresh-checkout Hunyuan I2V run has now completed generation,
all seven MP4 attack/extraction conditions and paired quality evaluation.
`results/fresh_checkout_completed.json` verifies source hashes, a clean checkout,
successful commands and the actual source/received video hashes. Correct bits
are clean512, noise512, compression485, blur512, drop376, insert423 and clip502,
each out of512; paired PSNR is29.3492dB and SSIM0.92999. This is one case, using
cached model/data assets and a previously prepared isolated dependency environment;
it does not establish all-model, baseline or quality-environment acceptance.
`results/cross_environment_diagnostic.json` records an important
limitation: despite identical case/key/message and matching clean bit counts,
the old and fresh decoded videos are not pixel-identical. Cross-run reference
PSNR is 41.00 dB and marked-video PSNR is 39.93 dB. These are not watermark
fidelity losses. Version, initial-noise, FFmpeg and Python-source checks are
recorded, but the cause remains unresolved; no bitwise reproduction claim is
made and this single-case evidence does not close the full acceptance checklist.

- [x] Core ELMC, CCTA and BCH implementation with mathematical tests.
- [x] Frozen numerical protocol and model repository revisions.
- [x] Explicit authorized L40-for-A800 hardware deviation.
- [ ] Clean-environment installation tested on documented supported hardware.
- [ ] Public data manifest, acquisition instructions, licenses and integrity checks.
- [ ] Reader-owned secret generation and persistent private run state.
- [ ] Public CLI for generation, embedding, blind extraction and attacks.
- [x] LAST on both HunyuanVideo and Wan2.2, both T2V and I2V, verified end to end on one integration case each (28 completed attack conditions; `results/last_backbone_integrations.json`). Full benchmarks and other methods remain incomplete.
- [ ] Reproducible SIGMark, VideoShield, VideoMark and LFG baseline integrations.
- [ ] Main-paper quality, robustness, efficiency, ablation and margin experiments.
- [ ] Supplement controls, coding diagnostics, stress tests and repeated timing.
- [ ] Official quality metrics with applicability denominators and no proxy substitution.
- [ ] Versioned manifests, deterministic seeds/maps, receipts and failure accounting.
- [ ] Table/figure generation from actual raw metrics, with uncertainty where specified.
- [ ] Historical-result reuse audit linking each reused observation to its exact protocol.
- [ ] Public example inputs/outputs that have redistribution permission.
- [ ] CI, installation smoke test and fresh-checkout reproduction walkthrough.
- [ ] Main README documents every paper experiment command and expected output schema.
- [ ] Third-party licensing, citation metadata and release archive/tag.
- [ ] Explicit discrepancies between measured results and manuscript targets.

Server paths, cached credentials and unpublished keys must never be prerequisites
for readers. Scheduler helpers may be local infrastructure, but all scientific
operations they dispatch must have documented repository entry points. Completion
means the full deliverable is independently runnable and audited, not merely that
some experiments passed or the repository contains source files.
